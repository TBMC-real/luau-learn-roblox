Introduction to Luau
Roblox's typed extension of Lua 5.1
Luau Roblox Studio Beginner

Luau is the scripting language used in Roblox. It's a fork of Lua 5.1 that Roblox has extended with optional static typing, better performance, and safer semantics. Every game mechanic — from moving parts to UI buttons to server logic — is powered by Luau scripts.

Scripts live inside Roblox's data model tree. There are three kinds you'll use constantly:

Script

Runs on the server. Handles game logic, data storage, and anything that should be authoritative.

LocalScript

Runs on the client. Controls UI, camera, input, and visual effects for the player.

ModuleScript

Returns a table of functions/values. Shared code imported by other scripts via require().

Your First Script

LUAUServerScript — Hello World
-- This is a comment
print("Hello, Roblox!")

-- Variables use local keyword
local playerName = "Player1"
print("Welcome, " .. playerName)
ℹ️
String concatenation in Lua uses .. (two dots), not +. This trips up most beginners coming from other languages.

Luau vs Standard Lua

String interpolation❌✅ \`Hello {name}\`

Variables & Types
Storing and working with data in Luau
TypesVariablesBeginner

Luau is dynamically typed by default — variables hold any type. You can optionally annotate types for tooling and safety.

The Basic Types

LUAUAll core types
local score: number  = 100        -- integer or float
local name: string  = "Roblox"    -- text
local alive: boolean = true       -- true / false
local nothing        = nil        -- absence of value

-- Roblox data types (not plain Lua)
local pos   = Vector3.new(0, 5, 0)
local color = Color3.fromRGB(255, 100, 0)
local cf    = CFrame.new(0, 10, 0)

Local vs Global

⚠️
Always use local. Global variables are stored in a shared table (_G), are slower to access, and cause hard-to-track bugs. In Roblox scripts, globals also pollute the environment in unexpected ways.
✅ Good
local speed = 16
local jump  = 50
❌ Avoid
speed = 16   -- global!
jump  = 50   -- global!

String Interpolation (Luau only)

LUAUTemplate strings with backticks
local level = 42
local msg = `You are level {level}!`
print(msg) -- "You are level 42!"

-- Compound assignment (Luau extension)
local coins = 10
coins += 5   -- coins is now 15
coins *= 2   -- coins is now 30

Control Flow
if/elseif/else, loops, and conditions
If/ElseLoopsBeginner

Conditionals

LUAUif / elseif / else
local health = 75

if health >= 100 then
    print("Full HP")
elseif health > 50 then
    print("Healthy")
elseif health > 0 then
    print("Low HP — danger!")
else
    print("Dead")
end
ℹ️
In Lua, only false and nil are falsy. The number 0 and empty string "" are truthy — the opposite of many other languages.

Loops

LUAUThree loop types
-- Numeric for: start, stop, step (step defaults to 1)
for i = 1, 10 do
    print(i)
end

-- While loop
local count = 0
while count < 5 do
    count += 1
end

-- Repeat until (checks condition at the END)
repeat
    count += 1
until count >= 10

-- break exits any loop
for i = 1, 100 do
    if i == 5 then break end
    print(i)
end

Functions
Defining, calling, and passing functions
FunctionsClosuresBeginner

Defining Functions

LUAUFunction syntax forms
-- Standard declaration
local function greet(name: string): string
    return "Hello, " .. name
end

-- Function stored in a variable
local double = function(x)
    return x * 2
end

-- Multiple return values
local function minMax(a, b)
    return math.min(a, b), math.max(a, b)
end

local lo, hi = minMax(3, 7)
print(lo, hi) -- 3   7

Variadic Functions

LUAUAccepting any number of arguments
local function sum(...)
    local total = 0
    for _, v in {...} do
        total += v
    end
    return total
end

print(sum(1, 2, 3, 4)) -- 10

Functions as Values (Callbacks)

LUAUPassing functions — used heavily in Roblox events
-- Roblox events use function callbacks
local part = workspace.Part

part.Touched:Connect(function(hit)
    print(hit.Name .. " touched the part!")
end)

Tables & Arrays
Lua's only data structure — used for everything
TablesArraysImportant

In Lua, tables are the single universal data structure. They serve as arrays, dictionaries, objects, and modules all at once.

Arrays (Sequential Tables)

LUAUTables as arrays — index starts at 1!
local fruits = {"apple", "banana", "cherry"}

print(fruits[1]) -- "apple"  (NOT 0!)
print(#fruits)   -- 3  (length operator)

-- Add to end
table.insert(fruits, "date")

-- Remove at index
table.remove(fruits, 2) -- removes "banana"

-- Iterate with ipairs (ordered, stops at nil)
for i, fruit in ipairs(fruits) do
    print(i, fruit)
end

Dictionaries (Key-Value Tables)

LUAUString-keyed tables
local player = {
    name   = "Swordsman99",
    level  = 15,
    coins  = 320,
    alive  = true,
}

-- Access with dot or bracket notation
print(player.name)           -- "Swordsman99"
print(player["level"])       -- 15

-- Add a field
player.guild = "Warriors"

-- Iterate with pairs (unordered)
for key, value in pairs(player) do
    print(key, "=", value)
end
💡
ipairs vs pairs: Use ipairs for arrays (stops at first nil, respects order). Use pairs for dictionaries (visits all keys, random order).

Services & Roblox API
Accessing Roblox's built-in systems
ServicesAPICore

Roblox provides services — singleton objects that expose functionality. You get them with game:GetService(). Never access them via long dot chains like game.Players in production — use GetService for reliability.

Essential Services

LUAUAccessing common services
local Players       = game:GetService("Players")
local RunService    = game:GetService("RunService")
local TweenService  = game:GetService("TweenService")
local DataStore     = game:GetService("DataStoreService")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local ServerStorage = game:GetService("ServerStorage")
local UserInputService = game:GetService("UserInputService")

Navigating the Hierarchy

LUAUFinding objects
-- Direct child
local part = workspace.MyPart

-- WaitForChild — safe for LocalScripts (async load)
local part = workspace:WaitForChild("MyPart")

-- FindFirstChild — returns nil if not found (safe)
local part = workspace:FindFirstChild("MyPart")
if part then
    print("Found: " .. part.Name)
end

Players & Characters
Detecting joins, accessing humanoids & parts
PlayersHumanoidCore

Player Joined / Left

LUAUServerScript — player lifecycle
local Players = game:GetService("Players")

Players.PlayerAdded:Connect(function(player)
    print(player.Name .. " joined!")

    -- Character may load AFTER PlayerAdded fires
    player.CharacterAdded:Connect(function(character)
        local humanoid = character:WaitForChild("Humanoid")
        print(player.Name .. " spawned with " .. humanoid.MaxHealth .. " HP")
    end)
end)

Players.PlayerRemoving:Connect(function(player)
    print(player.Name .. " left.")
end)

Humanoid Properties

LUAUWorking with Humanoid
local character = player.Character
local humanoid  = character:FindFirstChildOfClass("Humanoid")
local hrp       = character:FindFirstChild("HumanoidRootPart")

-- Common Humanoid properties
humanoid.Health           -- current HP
humanoid.MaxHealth        -- max HP (default 100)
humanoid.WalkSpeed        -- movement speed (default 16)
humanoid.JumpPower        -- jump height (default 50)

-- Take damage
humanoid:TakeDamage(25)

-- Death event
humanoid.Died:Connect(function()
    print(player.Name .. " died!")
end)
💡
HumanoidRootPart is the invisible part at the character's center. Use its CFrame or Position to teleport or track the player's world position.

Remote Events & Functions
Client ↔ Server communication
RemoteEventNetworkingImportant

The server and client run in separate sandboxes. To communicate between them you use RemoteEvents (fire-and-forget) and RemoteFunctions (request/response). Both live in ReplicatedStorage so both sides can access them.

Setup

LUAUCreate in Studio — then reference in scripts
-- In ServerScript OR ServerScriptService setup script:
local RS = game:GetService("ReplicatedStorage")

local evt = Instance.new("RemoteEvent")
evt.Name = "CoinCollected"
evt.Parent = RS

Firing Client → Server

LUAULocalScript fires; Script receives
-- LocalScript (client)
local RS  = game:GetService("ReplicatedStorage")
local evt = RS:WaitForChild("CoinCollected")

evt:FireServer(50)  -- send coin value to server

-- ──────────────────────────────────────────
-- Script (server)
local RS  = game:GetService("ReplicatedStorage")
local evt = RS:WaitForChild("CoinCollected")

evt.OnServerEvent:Connect(function(player, coinValue)
    print(player.Name, "collected", coinValue, "coins")
    -- update player's leaderstats here
end)

Firing Server → Client

LUAUServer fires; LocalScript receives
-- Script (server) — fire one player
evt:FireClient(player, "You got 50 coins!")

-- Script (server) — fire everyone
evt:FireAllClients("Server message to all")

-- LocalScript (client)
evt.OnClientEvent:Connect(function(msg)
    print(msg)
end)
⚠️
Never trust the client. Always validate data on the server side. A hacker can fire RemoteEvents with any arguments they want, so never do important game logic based purely on client input.

Coroutines & task Library
Async code, delays, and parallel execution
taskCoroutinesAdvanced

Roblox scripts are single-threaded, but you can simulate concurrency with coroutines and the task library. The task library is Roblox's preferred replacement for the older wait() and spawn() functions.

task Library (Preferred)

LUAUModern async with task.*
-- Delay execution (non-blocking)
task.delay(2, function()
    print("Runs 2 seconds later")
end)

-- Run on next frame (non-blocking)
task.spawn(function()
    print("Runs immediately in a new thread")
end)

-- Wait (yields current thread)
task.wait(1)
print("After 1 second")

-- Run on next Heartbeat
task.defer(function()
    print("Deferred to end of frame")
end)

Coroutines

LUAULow-level coroutine control
local co = coroutine.create(function()
    print("step 1")
    coroutine.yield()   -- pause here
    print("step 2")
end)

coroutine.resume(co) -- prints "step 1"
coroutine.resume(co) -- prints "step 2"

-- coroutine.wrap is a cleaner shorthand
local gen = coroutine.wrap(function()
    for i = 1, 3 do
        coroutine.yield(i)
    end
end)
print(gen()) -- 1
print(gen()) -- 2
Old (avoid)New (use)
wait(n)task.wait(n)
spawn(fn)task.spawn(fn)
delay(n, fn)task.delay(n, fn)

OOP & ModuleScripts
Classes, metatables, and reusable modules
OOPMetatablesAdvanced

Lua doesn't have built-in classes, but you can implement OOP using metatables. This is the standard pattern used in most serious Roblox projects.

Creating a Class

LUAUModuleScript: Enemy class
-- ModuleScript: Enemy
local Enemy = {}
Enemy.__index = Enemy

function Enemy.new(name: string, health: number)
    local self = setmetatable({}, Enemy)
    self.name   = name
    self.health = health
    return self
end

function Enemy:TakeDamage(amount: number)
    self.health -= amount
    if self.health <= 0 then
        print(self.name .. " defeated!")
    end
end

function Enemy:GetHealth(): number
    return self.health
end

return Enemy

Using the Module

LUAUServerScript — requiring a module
local RS    = game:GetService("ServerStorage")
local Enemy = require(RS.Enemy)

local boss = Enemy.new("Dragon Boss", 500)
boss:TakeDamage(150)
print(boss:GetHealth()) -- 350

Inheritance Pattern

LUAUExtending a base class
local BossEnemy = setmetatable({}, {__index = Enemy})
BossEnemy.__index = BossEnemy

function BossEnemy.new(name, health, phase)
    local self = Enemy.new(name, health)  -- call super
    return setmetatable(self, BossEnemy)
end

function BossEnemy:Roar()
    print(self.name .. " ROARS!")
end

return BossEnemy
💡
Module caching: require() caches its result. The second call to require() on the same module returns the exact same table — no re-execution. This makes modules perfect for shared state within one environment (server or client).
